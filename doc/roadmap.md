## 2. 소스별로 확인된 한계

### yfinance
- 어느 시장이든 접미사만 붙이면 된다 (`005930.KS`, `7203.T`, `BTC-USD`, `KRW=X`)
- 분기 재무제표·애널리스트 목표주가·기관 보유·ETF 상위 편입 모두 응답한다
- `earnings_dates`는 `lxml` 설치 후 동작한다 (25건)
- `.info`는 **종목당 약 0.9초**. 720종목이면 11분이라 일괄 수집 경로로는 못 쓴다
- **투자자 유형별 매매동향은 없다.** 미국 시장이 공개하지 않는 자료다

### KIS Open API (한국투자증권)
- 모의투자 서버로 시세 조회 전부 가능. 실전 키는 주문 API까지 열리므로 분리 보관
- `investor-trade-by-stock-daily` — 한 번에 30거래일, **기준일이 종료일**이라 뒤로 걸으면 소급된다
- 유량 제한이 빡빡하다. 간격 없이 부르면 `EGW00201`. 현재 0.6초 간격 + 재시도
- 국내주식 엔드포인트가 100개 이상. 아래 3절의 후보 다수가 여기 있다

### 지수 구성종목
- S&P 500 — 위키피디아. GICS 섹터·하위산업이 **표에 함께 들어 있다**
- 나스닥 100 — 위키피디아에서 표가 사라져 Slickcharts 사용 (2026-08 확인)
- 코스피 200 — 네이버 편입종목 페이지. 표에 코드가 없어 링크에서 추출
- KRX 업종 — KIND 상장법인목록. 요청 1회로 2,761개

### 막힌 길 (재시도해도 같은 결과)

| 시도 | 결과 |
|---|---|
| `pykrx` | KRX가 로그인을 요구한다 (`KRX_ID`/`KRX_PW`). 구성종목·티커 목록 모두 차단 |
| 네이버 `item/frgn.naver` | 에러 페이지. Referer·`.nhn` 경로 모두 무효 |
| 네이버 모바일 API | 외국인·기관·개인을 주지만 **10거래일 고정**. 페이지 파라미터 무시 |
| Invesco QQQ 보유종목 CSV | HTTP 406 |
| 위키피디아 나스닥 100 표 | 페이지에서 제거됨 |

## 3. 다음 후보

우선순위는 **비용 대비 커버리지**로 매겼다. 앞의 것일수록 적은 작업으로 많은 프롬프트가 풀린다.

### 3.1 지금 시작해야 하는 것 — 스냅샷 적재

**늦을수록 손해다.** 아래 값들은 API가 "현재 값"만 주고 이력을 주지 않는다.
오늘 쌓기 시작한 날부터 시계열이 생기며, 과거로는 영원히 소급되지 않는다.

- 증권사 목표주가·투자의견 (yfinance `analyst_price_targets`)
- 시가총액
- 지수 편입·편출 이력 (`index_members`는 현재 상태만 담는다)

questions.md에서 "목표가 **변화**", "추정치 **상향** 여부"를 묻는 프롬프트가 전부 여기 걸린다.

### 3.2 분기 재무 (미국·한국)

yfinance의 `quarterly_income_stmt` / `balance_sheet` / `cashflow`로 이미 응답을 확인했다.
매출·영업이익률·재고자산·영업활동현금흐름·부채비율이 나온다.
6번 챕터(실적 발표 해석) 10개 프롬프트가 여기에 달려 있다.

### 3.3 시장 폭 (breadth)

720종목 일별 시세가 이미 있으므로 **추가 수집 없이** 계산된다.
상승/하락 종목 수, 20일선 위 비율, 52주 신고가 종목 수, 업종별 상대강도.
18번 챕터(상승장이 끝나기 전 신호) 10개가 대응된다.
종목 단위가 아니라 유니버스 집계라 `/market` 화면이 따로 필요하다.

### 3.4 신용잔고 · 공매도 (한국)

KIS에 엔드포인트가 있고 **날짜 파라미터를 받는다**.

```
daily_credit_balance   FHPST04760000   신용잔고 일별
daily_short_sale       FHPST04830000   공매도 일별
```

`investor_flows`와 같은 구조로 쌓으면 된다. 수집 로직은 재사용 가능.

### 3.5 프로그램 매매 · 회원사별 매매 (한국)

```
program_trade_by_stock_daily   FHPPG04650201
inquire_member_daily           FHPST04540000   증권사별 매매
```

### 3.6 테마 (한국 전용)

네이버 테마 266개가 questions.md가 말하는 업종 목록과 거의 일치한다
(`2차전지(생산)`, `원자력발전`, `반도체 대표주` 등). 표준 업종과 달리 **한 종목이 여러 테마에
속하므로** 컬럼이 아니라 다대다 테이블이 필요하다. 미국에는 대응하는 무료 소스가 없다.

### 3.7 공시 (DART)

OpenDART는 무료이고 API 키만 받으면 된다. 수주·계약 공시 이후 주가 반응을 보는
프롬프트(2번 챕터)가 여기 달려 있다. 미국은 SEC EDGAR.

## 4. 자동 수집이 어려운 것

기술적 한계가 아니라 **성격상** 안 되는 것들이다. 무리해서 붙이지 않는다.

- **뉴스 톤·컨퍼런스콜 발언·리포트 요지** — 원문 수집까지가 한계고 해석은 LLM의 몫
- **검색량·커뮤니티 언급** — 구글 트렌즈 등 별도 API. 비공식이고 불안정
- **계좌 정보** — 보유 수량, 평균 단가, 현금, 목표 수익률. 사용자 입력의 영역
- **투자 심리** — 8번 챕터 전체. 데이터가 아니라 사용자가 답할 질문지다

## 5. 구조를 손봐야 할 것

기능이 아니라 빚에 가까운 항목들이다.

- **`전체 업데이트` 버튼이 동기 요청이다.** 720종목을 2000년부터 다시 받으면 수 분간
  브라우저가 묶인다. 일괄 수집처럼 백그라운드로 옮겨야 한다
- **마이그레이션 도구가 없다.** `ensure_columns()`가 빠진 컬럼을 채우지만 컬럼 삭제나
  타입 변경은 다루지 못한다. 스키마가 더 커지면 Alembic을 들일 시점이다
- **한국 종목의 GICS 섹터가 비어 있다.** 네이버 업종 79개를 GICS 11섹터로 올리는
  매핑표가 필요하다. 손으로 만들 분량이지만 GICS 개정 때마다 낡는다
- **통화 표시가 없다.** 종가 `271,000`이 원화인지 달러인지 화면에서 구분되지 않는다
- **스크리너가 미국 대형주 50종목에 고정돼 있다.** 이제 720종목이 캐시돼 있으므로
  풀을 캐시 기준으로 바꾸고 지수·업종 필터를 붙일 수 있다
