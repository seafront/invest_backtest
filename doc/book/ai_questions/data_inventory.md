# questions.md 데이터 인벤토리

`doc/book/ai_questions/questions.md`(36개 챕터, 330개 프롬프트)에서 요구하는 데이터를
**시스템 자동 수집 가능 여부** 기준으로 분류함.

- 등급 **A** — 지금 있는 OHLCV만으로 계산 가능 (파생 지표)
- 등급 **B** — 외부 소스 추가 연동 필요, 무료/공개 API 존재
- 등급 **C** — 수집 가능하나 유료·크롤링·비정형
- 등급 **D** — 자동 수집 불가 (사용자 입력 또는 LLM 정성 판단)

> 전제: 현재 저장소는 yfinance 기반 **미국 주식** OHLCV만 캐싱함(`stocks` 테이블).
> 반면 questions.md는 **한국 시장**(외국인·기관 수급, 신용잔고, 연기금/투신 등) 전제가 다수.
>
> **한국 데이터는 한국투자증권 KIS Open API 하나로 대부분 커버된다.** 국내주식만 156개
> 엔드포인트를 제공하며, 이전에 C등급(유료·크롤링)으로 분류했던 컨센서스·투자의견·
> 재무제표가 여기 무료로 들어 있다. 아래 표의 B등급 소스는 KIS를 1순위로 표기했다.
> KIS 조회 API는 대체로 최근 30~100건 제한이라 **매일 적재해 시계열을 쌓는 구조**가 전제다.
> 과거 소급 적재가 필요하면 `pykrx`(KRX 계정 필요) 병행.

## A. 지금 데이터(OHLCV)만으로 계산 가능

### A-1. 기존 항목 (1~20장)

| 데이터 | 계산 방식 | 사용 프롬프트 예 |
|---|---|---|
| 기간 수익률 (5·10·20거래일, 1·3·6개월, 1년) | 종가 비율 | 2, 4-2, 9-2, 13-1 |
| 이동평균선 5·20·60·120일, 정배열 여부 | 종가 SMA | 4-1, 4-3, 10-1 |
| 이격도 (종가 / 20일선) | 파생 | 4-2, 9-7, 19-1 |
| 거래량·거래대금 (5·20·60일 평균, 증가율, 배율) | 종가×거래량 | 2, 9-4, 11-1 |
| 52주 신고가·신저가 / 전고점·전저점 | rolling max/min | 18-3, 10-2 |
| 고점 대비 낙폭, MDD, 회복 소요 거래일 수 | 파생 | 12-1, 12-4 |
| 윗꼬리·아랫꼬리 길이, 종가 위치 (고가 대비) | (고가−종가)/전일종가 등 | 19-2, 19-4 |
| 장중 회복률 (저가→종가), 음봉 후 반등 여부 | 파생 | 11-3 |
| 양봉 일수, 5일선 위 체류일 수 | 파생 | 11-8, 22-2 |
| 변동성 (일간 등락폭 σ, 장중 고저폭, ATR) | 파생 | 13-4, 18-7 |
| 저점 절상 여부, 박스권 폭, 고점 압축 구간 | swing low/high 탐지 | 11-2, 11-4 |
| 돌파 실패 횟수 / 저항 가격대 | 고점 근접 후 종가 하락 카운트 | 19-3, 22-8 |
| 매물대(가격대별 거래량 프로파일) | 일봉 근사 (정확도는 틱 필요) | 10-4, 11-9, 23-4 |
| 지수 하락일 개별 종목 방어력, 상대강도, 베타 | 지수 시계열과 조인 | 11-5, 13-4, 27-7 |
| 시장 폭: 상승/하락 종목 수, 20일선 위 종목 비율 | 전종목 OHLCV 필요 | 18-1, 18-8 |
| 52주 신고가 종목 수 추이 | 전종목 | 18-3 |
| 시총 상위 10종목 지수 기여도 | 전종목 + 시총 | 18-2 |
| 업종별 수익률·거래대금 (업종 매핑 있으면) | 집계 | 5-4, 12-6, 28-1 |

### A-2. 신규 항목 (21~27장) — **차트·거래량 파생, 추가 소스 불필요**

21~27장 70개 프롬프트는 거의 전부 OHLCV 파생이다. **자동화 난이도 대비 커버리지가
가장 좋은 블록**이며, 지금 엔진에 바로 붙는다.

| 데이터 | 계산 방식 | 사용 프롬프트 예 |
|---|---|---|
| 이동평균선 **기울기** 변화 (5·20·60일선, 10거래일) | SMA 1차 차분 | 22-5, 26-7 |
| 평균선 **간격** (5–20일선, 20–60일선), 확대/축소 추이 | SMA 차 / 종가 | 22-6 |
| 20일선 이격도 밴드 (+5%/+10%/+15% 구간 분류) | 파생 | 22-7, 36-5 |
| 정배열 전환 초기 신호 (골든크로스 + 체류일 결합) | 파생 | 22-9 |
| 박스권 상단·하단·중앙값 (30거래일), 가격 압축 여부 | rolling max/min + 폭 축소 | 23-1, 25-1 |
| 하단 **방어 횟수** (장중 저가 이탈 후 종가 회복 카운트) | 저가<지지 & 종가>지지 | 23-2, 26-8 |
| 상승일 vs 하락일 **거래대금 비율** | 조건부 집계 | 23-3, 19-8 |
| 큰 음봉 이후 3·5거래일 회복률 | 이벤트 기준 forward return | 23-5 |
| 박스권 상단 접근일의 종가 위치·윗꼬리·익일 흐름 | 이벤트 집계 | 23-6, 24-2 |
| **지지/저항 구간 클러스터링** (단일 가격 아닌 밴드) | swing point 군집화 | 24-1, 24-2, 24-3 |
| 지지 이탈 후 회복 여부 (장중/종가 구분) | 파생 | 24-4, 21-6 |
| 돌파 후 **되돌림 성공** 판정 (저항→지지 전환) | 이벤트 시퀀스 | 24-6, 25-6 |
| 지지력/저항력 **약화** 추이 (반등 폭·밀림 폭 감소) | 이벤트별 회귀 | 24-7, 24-8 |
| 돌파일 거래량 / 20일 평균 **배율** | 파생 | 25-4, 23-9 |
| 종가 안착 여부 (장중 돌파 vs 종가 돌파) | 고가>저항 & 종가<저항 | 25-2 |
| 박스권 **재진입** 여부 및 소요 거래일 | 이벤트 시퀀스 | 25-5 |
| 실패한 돌파 사례 목록 (6개월) | 이벤트 스캔 | 25-9 |
| 저점 배열 비교 (연속 swing low 방향) | swing low 시퀀스 | 26-2 |
| 반등 구간 길이·횟수·반등률 | 구간 분해 | 26-3 |
| 눌림 폭 변화 (구간별 낙폭 축소 추이) | 구간 분해 | 26-4 |
| 되돌림 속도 (하락 후 회복까지 거래일 수) | 이벤트 기준 | 26-5, 12-4 |
| 관심종목 다중 분류 (검토군/관찰군/위험군/제외군) | 위 지표들의 규칙 조합 | 27-1 ~ 27-10 |

→ **전종목 일봉 수집이 선행 조건.** 현재는 티커 단위 on-demand 캐싱이라
   시장 폭·업종 확산·스캔형(21-9, 23-9, 27장 전체, 28장) 프롬프트는 불가.

## D. 자동 수집 불가 — 사용자 입력 또는 LLM 정성 판단

| 항목 | 처리 방식 | 사용 프롬프트 예 |
|---|---|---|
| 보유 수량, 평균 매수가, 손실률, 계좌 평가액, 현금 잔고 | **사용자 입력 폼 / 포트폴리오 테이블** | 15-3, 15-4, 15-7, 15-9 |
| 목표 수익률, 손절 기준, 투자 기간, 감내 변동성 | 사용자 설정 | 14-8, 16-4, 32-1 |
| **투자 일지 본문 (매수 근거·장중 행동·매도 이유)** | **사용자 기록 — 32장 10개 프롬프트 전부** | 32-1 ~ 32-10 |
| **AI 답변 원문 (검증 대상 텍스트)** | 사용자 붙여넣기 — 34·35장 대부분 | 34-6, 34-7, 35-1, 35-10 |
| 공포·포모·본전 심리·복수 매매 판정 | LLM 판단 (챕터 8 전체) | 8-1 ~ 8-10 |

## 권장 수집 순서

1. **전종목 일봉 확장** — 현재 티커 단위 캐싱을 전종목 배치 적재로
   → A 등급 전부 해금. **21~27장 70개 프롬프트가 여기서 대부분 해결된다.**
2. **차트 파생 지표 라이브러리** — swing point 탐지, 박스권/지지·저항 클러스터링,
   돌파·되돌림 이벤트 판정. 22~26장의 공통 기반이고 재사용도가 가장 높다.
3. **KIS 연동 (조회 API)** — 투자자별 수급, 공매도, 신용잔고, 대차잔고, 시총, PER/PBR
   → 챕터 2·5·13·18·21·33 해금. 조회 제한이 있으므로 **일별 적재 배치**로 설계.
4. **KIS 재무·컨센서스** — 재무제표 6종 + 추정실적 + 투자의견
   → 챕터 6·31·33·35 해금. 이전 C등급 병목이 여기서 풀린다.
5. **OpenDART 연동** — 공시 원문 + 현금흐름표·재고자산 (KIS 재무 API 미포함 항목)
   → 챕터 7-3·29-3·33-9 해금
6. **업종 매핑 + 업종 집계** — 챕터 28, 5-4, 12-6
7. **거시 지표 확장 (FRED·ECOS)** — 금리·환율·유가·원자재 → 챕터 14·31·36
8. **포트폴리오 + 투자 일지 입력 테이블** — 챕터 15·16·20·32
9. 뉴스 수집(네이버 API) + 검색량 — 관심도 지표
10. 메모리 가격·가동률·수주잔고 — 마지막 (비정형, 비용·법적 검토 필요)

## 리뷰 메모

- **21~27장이 이 문서의 핵심 발견.** 70개 프롬프트가 추가 데이터 소스 없이
  OHLCV 파생만으로 구현 가능하다. 지금 저장소의 백테스트 엔진과 가장 가깝다.
- **33장은 사실상 스크리너 요구사양서**다. 제외 조건 → 재무 → 거래대금 → 수급 →
  가격 위치 → 뉴스 → 단기/중기 → 위험 → 최종 분류의 9단계 파이프라인이 그대로 적혀 있다.
  현재 `services/screener.py`의 2단계 스크리너를 확장할 때 그대로 참조 가능.
- **36장은 신규 데이터가 없다.** 1~35장의 조합을 시점(장전/장중/장마감)으로 배치한 것이라,
  데이터 문제가 아니라 **스케줄링·알림 문제**로 봐야 한다.
- **29·30장은 자동화 난이도가 가장 높다.** 메모리 현물가, 가동률, 수주잔고, AI 매출 비중은
  정형 API가 없다. 이 두 챕터는 LLM + 수동 입력 하이브리드로 두는 편이 현실적이다.
- **32·34장은 데이터 수집 대상이 아니다.** 사용자가 쓴 일지와 AI가 낸 답변이 입력이므로,
  필요한 것은 데이터 파이프라인이 아니라 **텍스트 입력 UI와 저장소**다.
- 챕터 1~3은 `### N)` 소제목 없이 불릿만 사용해 나머지 33개 챕터와 형식이 다르다.
  목차 생성 스크립트(`update_toc.py`)가 `###`만 인식하므로 세부 항목이 목차에 안 잡힌다.
